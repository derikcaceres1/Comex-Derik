COMEX NM v2 — Filtro de upload

Alinhamento sobre o filtro que decide o que sobe para a plataforma. Validação rápida antes de mexermos.

Contexto

Antes de subir o gold para a plataforma, o pipeline já consulta a API Cost Drivers para descobrir, por ID, qual é a maior data já publicada (max_data). O upload então é filtrado por essa data — só sobe o que estiver "à frente" do que já existe.

A linha que faz isso, hoje, na costdrivers_comex_NM.py (v1) é: 

df_fob_id = df_fob_id[df_fob_id['Data'] >= max_data]

O ponto de atenção

O operador é >= (maior ou igual). Isso significa que, todo upload, o último mês de cada ID já publicado é re-enviado — porque a Data dele é igual a max_data e cai dentro do filtro.

Exemplo prático

CenárioComportamento
Plataforma já tem Out/2025 publicado para o ID X.
Pipeline calcula gold com Out/2025 e Nov/2025.		 Upload envia Out/2025 (sobrescreve o publicado) e Nov/2025 (novo).
Comportamento: revisão do mês já publicado.

O que precisamos confirmar com vocês

Pergunta Esse comportamento — re-enviar todo o último mês já publicado a cada upload — é o esperado?

  • Se a plataforma faz deduplicação ou aceita sobrescrita silenciosamente, o efeito é nulo e podemos manter como está.
  • Se a regra é "dados de COMEX não devem ser revisados" (no sentido estrito de não tocar mês já publicado), basta trocar >= por > em uma linha — sem nenhum outro impacto.

As duas opções, lado a lado

Opção Linha Efeito
Manter (como hoje) Data >= max_data Re-envia o último mês publicado a cada execução. Se a plataforma deduplica, ok.
Trocar (mínimo) Data > max_data Só sobe meses estritamente novos. Mês publicado nunca é tocado.

Posição atual no v2

decisão Por enquanto o método upload() do v2 está idêntico ao da v1 (mantido o >=). A única adição é a guarda NMConfig.allow_upload, que por padrão é False — nada sobe sem aprovação explícita. Aguardamos a confirmação de vocês para decidir se trocamos ou não.

Resumo

  • Pergunta única: a plataforma deduplica o último mês ou precisamos trocar >= por >?
  • Custo da troca: 1 caractere. Sem impacto no cálculo, no histórico, nos filtros, no gold.
  • Risco de manter: revisão silenciosa do último mês a cada upload (se a plataforma não dedup).
